# Jobseeker · 寻职者

一个温暖纸张风格的求职工作台：发现岗位、定制真实简历、记录投递进度。按照上一级目录的《求职Agent工具-黑客松方案.md》实现的本地 Web 应用。

## 立即启动

**部署到 Netlify（完整功能）：** 前端、AI/搜岗、文档处理、邮箱后台任务与加密存储已适配。运行 `npm run deploy:netlify` 发布；首次配置、免登录访问和数据迁移见 [DEPLOY-NETLIFY.md](DEPLOY-NETLIFY.md)。不要只上传 `dist`，那不会发布后端。

需要 Node.js 22.13 或更新版本；首次运行请执行 npm install。

**Windows：** 双击本目录的 `start.cmd`，保持终端运行，在浏览器打开：

```text
http://localhost:4173
```

也可以在此目录执行：

```powershell
npm start
```

端口被占用时：

```powershell
$env:PORT = '4174'
npm start
```

然后打开 `http://localhost:4174`。停止服务：在启动终端按 Ctrl+C。不要直接双击 `index.html`：ES Modules 和 JSON 数据需要通过 HTTP 加载。

`server.mjs` 提供静态页面、AI 代理、简历文档处理和邮件接口，默认仅监听 `127.0.0.1`。

## 推荐体验路径

1. 发现岗位：搜索「前端」，选择城市，查看一个岗位的匹配说明。
2. 点击收藏，岗位将进入投递手账；在详情中点击「为此定制简历」。
3. 在简历工作室编辑自己的真实信息，选择模板，点击整理按钮。
4. 核对原始信息，单独确认推断。补充建议必须先改写为真实经历，才能写入简历。
5. 导出 Markdown 或 PDF，保存一个版本。
6. 在投递记录中关联该版本，更新进度、面试时间，并查看历史。
7. 查看洞察，在设置中导出完整备份。

演示讲解脚本与答辩提纲见 `DEMO.md`。

## AI 接入

演示岗位和真实岗位使用同一套 AI 能力。Netlify 部署默认通过服务端代理调用阿里云千问；示例档案、示例岗位和真实资料都会经过 AI 分析、整理或匹配。页面也不依赖外部字体、CDN 或第三方脚本。

线上评委体验无需填写密钥或切换模式。需要改用其他模型时，可在偏好设置中填写：

- **协议**：OpenAI Responses、OpenAI 兼容 Chat Completions，或 Claude Messages。
- **完整接口 URL**：包含完整路径，例如 `/v1/responses`、`/v1/chat/completions` 或 `/v1/messages`。国内服务请选择其明确支持的兼容协议和完整地址。
- **模型 ID**：按照所选服务控制台填写，不默认依赖方案中已可能过时的模型名称。
- **API Key**：默认仅存页面内存；可选择保存在当前标签页的 `sessionStorage`。从不写入 localStorage 或导出文件。
- **数据发送确认**：确认点击 AI 功能时向所配置地址发送该任务所需的数据。

「测试连接」只发送测试内容，不发送档案。真实接口调用有 30 秒超时、错误处理、输出格式验证；失败会显示错误，不会伪装成真实 AI 成功。

纯前端直连是否可用取决于服务的 CORS、账号、模型和网络条件。Netlify 版本通过服务端代理保管密钥，点击 AI 功能会调用已配置的服务；未配置服务的本地环境会提示配置问题，不会将本地规则包装成 AI 响应。

## 事实溯源与导出规则

- `USER`：原始档案内容；AI 返回内容只有与原始事实逐字一致时才保留此标签。
- `AI-INFER`：推断、总结或改写，需用户逐条核实。
- `AI-SUGGEST`：信息不足时的补充建议，不是个人经历，不能直接导出。
- 所有新生成草稿都处于待确认状态，包括原文摘录。原始信息可批量确认；推断需要单独确认。
- Markdown、PDF 和版本保存只采用已确认事实，并再次排除补充建议。
- 直接输入的档案信息是用户原始内容；编辑原始档案会使旧的生成稿失效，预览恢复为新档案，之后可重新生成。
- 示例档案始终明确提示其示例身份；请勿将虚构示例经历用于实际求职。

**PDF 实现说明：** 为保持零外部依赖和可选择的中文文字，本项目使用 A4 打印样式及浏览器「另存为 PDF」，替代原方案的 html2canvas 截图 PDF。点击 PDF 后选择「另存为 PDF」，关闭浏览器页眉/页脚；纸张选择 A4。某些嵌入式预览浏览器不支持打印，请在系统 Chrome / Edge 中打开网站导出。

## 数据与提醒

- localStorage：档案、偏好、投递记录、自定义岗位、当前简历草稿。
- IndexedDB：已确认的简历历史版本。
- JSON 备份同时包含以上两种存储，排除 API Key。导入会验证记录、状态、日期和版本结构，并提示替换范围。
- 导入和重置前自动导出当前完整备份；线上导入后仍使用统一 AI 服务，导入本身不会触发 AI 请求。
- 数据按浏览器和站点地址隔离。`localhost:4173` 与 `127.0.0.1:4173` 是不同工作区，切换端口也不会自动共享数据。
- 提醒在页面打开时每分钟重新计算：投递 3 天无回复、面试前 24 小时、Offer 截止前 48 小时或已过期。不具备关闭网页后的后台推送。
- 漏斗统计历史上已到达的阶段，并将直接进入后续阶段视为跨过前置阶段；不代表每家公司都安排了笔试。已结束记录保留历史。
- 联网搜岗由已配置的 AI 服务处理；邮箱读取需连接并授权，真实邮件投递必须在预览中确认。示例档案和演示岗位仍进行模拟投递，岗位匹配、简历整理和洞察分析同样使用 AI。

## 检查与测试

安装依赖后运行：

```powershell
npm run check
npm test
```

`check` 验证 JavaScript 语法、JSON、内置岗位和入口资源。Node 内置测试覆盖匹配筛选、状态变更、漏斗、提醒、事实确认、导出过滤、备份验证、HTML 转义、CSV 公式防护、协议解析、授权门禁与请求超时。

可选的 Playwright 回归脚本：

```powershell
npm install --no-save playwright
npx playwright install chromium
# 另开终端，保持 npm start 运行
npm run test:e2e
```

可通过 `BASE_URL` 指向其他本地端口，通过 `CHROMIUM_PATH` 使用已有浏览器，或通过 `PLAYWRIGHT_MODULE` 指定现有 Playwright 入口文件。脚本使用独立的浏览器上下文，不修改你已打开的工作区。截图、下载校验文件和打印预览写入被 Git 忽略的 `artifacts/`。设置 `RECORD_DEMO=1` 可同时记录浏览器操作视频。实际验证记录见 `TESTING.md`。

    job-search.js            岗位检索与 JD 导入
    resume-builder.js        档案、事实确认、预览与导出
    tracker.js               看板、列表、记录与邮件识别

    settings.js              配置、备份、主题
    utils.js                 通用 UI 与输出工具
  data/                      60 条岗位及 4 种简历模板
  assets/icons/logo.svg      本地矢量标志
  scripts/                   数据生成与静态检查
  tests/                     单元测试和可选浏览器回归

可直接部署 `index.html`、`css/`、`js/`、`data/`、`assets/` 到支持 HTTPS 的静态托管。无需构建，Hash 路由无需服务器重写。部署前明确 API 代理与数据持久化需求；本 MVP 不提供账户体系或跨设备同步。
